The CLI is the recommended route for local and agent workflows. It runs without
a custom MCP server. Use Node.js 22.12.0 or newer.

## 1. Run the CLI

```bash
npx --package=https://github.com/BintzGavin/shiplet-core/releases/download/cli-v0.1.0/bintzgavin-shiplet-0.1.0.tgz shiplet --help
npm install -g https://github.com/BintzGavin/shiplet-core/releases/download/cli-v0.1.0/bintzgavin-shiplet-0.1.0.tgz
```

The unscoped `npx shiplet` is an unrelated project. The scoped npm release is
pending; the GitHub tarball is the installable route. See [CLI setup](/docs/cli).

## 2. Prepare your build

```bash
shiplet prepare ./dist --name "Review build" --subdomain review-build --visibility organization --dry-run --json
```

Replace `./dist` with your file or static build folder. Check the dry-run output,
then rerun without `--dry-run`. Approve the browser session on the same computer.
The CLI preserves folder paths, defaults to organization visibility, and returns
the review URL. `shiplet login`, `shiplet whoami`, and `shiplet logout` manage the
session; later commands reuse it for two hours by default.

## 3. Review and collect feedback

Open the returned review URL and leave a harmless comment. Find the ticket in
[Feedback](https://shiplet.cc/feedback). Feedback replies and status changes are
available in the browser; the CLI does not expose those commands yet.

## Browser alternative

Use this path if you cannot install or run Node.js.

### Open the Prepare page

[Open the Shiplet app](https://shiplet.cc/). Sign in when asked. Shiplet creates
a default workspace for a first-time user and returns to the Prepare page.

### Choose the work to review

Keep **Upload files** selected, then choose one or more supported files: static
HTML, CSS, JavaScript, images, video, audio, PDFs, source code, structured data,
documents, archives, or GIS data. Use the CLI to preserve folder paths. Choose
**URL** when the artifact already has a public preview origin.

Shiplet renders common browser media directly. It shows readable text for UTF-8
code, JSON, configuration, and text GIS formats. Binary formats receive file
details and a user-initiated download. Executables and installers are rejected.

Name the artifact and choose its review subdomain. Before publishing, choose who
can see the review:

- **Organization** is the safe default for an internal review.
- **Private** limits access to administrators, owners, and people with an
  explicit grant.
- **Unlisted** allows anyone with the link to open the review.
- **Public** allows anonymous access and discovery.

View access does not grant edit access. Confirm the visibility, then select
**Prepare for review**.

### Open the review link

Shiplet places the artifact inside a sandboxed frame and shows trusted review
controls around it. Leave a harmless comment, then open the Shiplet detail page
or global Feedback view to find the ticket.

Read [Review feedback](/docs/review-feedback) for replies and ticket status.
Read [Access control](/docs/access-control) before sharing the link.

## Working with an agent

Give your agent the [CLI guide](/docs/cli), let it check the artifact with
`shiplet prepare --dry-run`, then approve publishing in your browser.
A custom MCP server is not required. [Code Mode MCP](/docs/code-mode-mcp) is
optional when your organization permits it and your agent needs API discovery
or feedback operations beyond the CLI command set.

## Troubleshooting

| Problem | Safe recovery |
| --- | --- |
| A file is rejected | Remove the unsupported or oversized file and prepare again. |
| The subdomain is unavailable | Choose another lowercase, hyphenated review name. |
| Publishing fails | Keep the local artifact and retry after the reported problem clears. |
| Sign-in or access is denied | Sign in with the invited email or ask an owner for the required viewing grant. |
| An external URL cannot load | Confirm it is public HTTPS on a standard port and does not redirect to a private address. |
| Review controls are unavailable | Reload the review link and sign in if asked. |
