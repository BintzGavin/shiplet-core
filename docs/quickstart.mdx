Share a build and the agent session that made it, then choose who sees each.
Use Node.js 22.12.0 or newer; no source checkout, global install, or npm account
is required.

## Ask your agent

The fastest way is to ask the agent that did the work. In Claude Code, Codex, or
any agent that can run commands, say:

```text
Publish ./dist to Shiplet for review, then share this session to it.
```

The agent runs `npx shiplet-cli prepare` and `npx shiplet-cli trace share
--current`, and you approve the sign-in in your browser. On a cloud agent with
no browser, it signs in with a code you approve on any device; see
[Choosing how to sign in](/docs/authentication).
[Code Mode MCP](/docs/code-mode-mcp) is also supported: an agent connected over
MCP can do the same without the CLI.

## Or run it yourself

### 1. Run the CLI

```bash
npx shiplet-cli --help
```

Use `npx shiplet-cli` for Shiplet; `npx shiplet` is an unrelated project.
See [CLI setup](/docs/cli) for global installation and the full command reference.

### 2. Publish the artifact

```bash
npx shiplet-cli prepare ./dist --name "Review build" --subdomain review-build --visibility organization --dry-run --json
```

Replace `./dist` with your file or static build folder. Check the dry-run
output, then rerun without `--dry-run` and approve the browser session on the
same computer. The CLI returns the review link. Organization visibility is the
safe default, and view access never grants edit access. Use
`npx shiplet-cli login`, `npx shiplet-cli whoami`, and `npx shiplet-cli logout`
to manage the session; later commands reuse it for two hours by default.

### 3. Share the session

```bash
npx shiplet-cli trace share --current --shiplet <id> --dry-run
```

Check what would be sent, then rerun without `--dry-run`. Secrets are masked on
your computer first, and the trace stays private until you share it. For a
session with no artifact, use `--new` instead of `--shiplet`.

### 4. Choose who sees what

The artifact follows its visibility. Give the trace its own audiences and
levels, for example the whole organization at Conversation and one reviewer at
Full:

```bash
npx shiplet-cli trace audiences <trace> --shiplet <id> --audience organization=conversation --audience email:dana@example.com=full
```

Or open the trace and use its **Sharing** panel, with **Preview as this
audience** to check before you share. Read [Traces](/docs/traces) and
[Access control](/docs/access-control).

### 5. Review and collect feedback

Open the review link and leave a harmless comment on the work. It keeps the
revision it was left on. Find the ticket in [Feedback](https://shiplet.cc/feedback),
reply, and update its status in the browser. Read
[Review feedback](/docs/review-feedback) for ticket work.

## Browser alternative

Use this path if you cannot install or run Node.js.

### Open the Prepare page

[Open the Shiplet app](https://shiplet.cc/). Sign in when asked. Shiplet creates
a default workspace for a first-time user and returns to the Prepare page.

### Choose the work to review

Keep **Upload files** selected, then choose one or more supported files: static
HTML, CSS, JavaScript, images, video, audio, PDFs, source code, structured data,
documents, archives, or GIS data. Use the CLI to preserve folder paths. Choose
**URL** when the artifact already has a public preview origin.

Shiplet renders common browser media directly. It shows readable text for UTF-8
code, JSON, configuration, and text GIS formats. Binary formats receive file
details and a user-initiated download. Executables and installers are rejected.

Name the artifact and choose its review subdomain. Before publishing, choose who
can see the review:

- **Organization** is the safe default for an internal review.
- **Private** limits access to administrators, owners, and people with an
  explicit grant.
- **Unlisted** allows anyone with the link to open the review.
- **Public** allows anonymous access and discovery.

View access does not grant edit access. Confirm the visibility, then select
**Prepare for review**.

### Open the review link

Shiplet places the artifact inside a sandboxed frame and shows trusted review
controls around it. Leave a harmless comment, then open the Shiplet detail page
or global Feedback view to find the ticket.

Read [Review feedback](/docs/review-feedback) for replies and ticket status.
Read [Access control](/docs/access-control) before sharing the link.

## Troubleshooting

| Problem | Safe recovery |
| --- | --- |
| A file is rejected | Remove the unsupported or oversized file and prepare again. |
| The subdomain is unavailable | Choose another lowercase, hyphenated review name. |
| Publishing fails | Keep the local artifact and retry after the reported problem clears. |
| Sign-in never completes | On a computer without a browser, use `npx shiplet-cli login --device`. |
| Sign-in or access is denied | Sign in with the invited email or ask an owner for the required viewing grant. |
| An external URL cannot load | Confirm it is public HTTPS on a standard port and does not redirect to a private address. |
| Review controls are unavailable | Reload the review link and sign in if asked. |
